## Exception and progress evidence

On exception, preserve locally the full Python traceback, exact exception class
and message, active fixture/check, stage/substage, function and input summary,
completed rows, marker path/state and current commit. Local evidence stays under
ignored `outputs/continuous_occlusion_failure_localization/local/`.

The public failure summary contains a sanitized message and traceback frames
sufficient to identify repository-relative module, function and line. Replace
the repository and other absolute path prefixes with stable tokens. Do not alter
the exception itself. Reject credentials, provider identities, private paths and
unapproved fields. The public summary may contain source lines only from the
new diagnostic adapter or the unchanged Session 14g engineering path.

Progress uses LF CSV with one row per completed engineering fixture. Append and
flush after every success. On closure, copy the accumulated bounded records into
the public `engineering_progress.csv`; never reconstruct completed rows from an
exception. The exclusive marker is created atomically before reproduction. A
marker or output collision stops before executing the target and is not the
governed reproduction.

## Single reproduction, outputs and decisions

After committing tested diagnostics, execute the exact engineering path once
through the diagnostic adapter. Create the exclusive marker first. Stop at the
first exception. If all engineering checks complete, close as UNRESOLVED and do
not enter downstream acceptance. There is no automatic retry.

Public outputs are exactly:

- `diagnostic_contract.json`
- `engineering_progress.csv`
- `failure_summary.json`
- `qc.json`
- `manifest.json`

All writes are atomic except the explicitly append-only ignored progress ledger.
JSON must be finite and schemas strict. The manifest binds protocol,
implementation, Session 14g authority, environment and four preceding output
hashes; its own hash is recorded in the report.

Choose one closure:

- **LOCALIZED — EXACT TYPEERROR SOURCE ESTABLISHED** only when the governed
  reproduction yields an unambiguous active fixture, operation and traceback.
- **UNRESOLVED — HISTORICAL FAILURE NOT SUFFICIENTLY LOCALIZED** if the failure
  does not reproduce or the evidence is ambiguous.
- **INVALID — LOCALIZATION EXECUTION FAILURE** for a defect in Session 14h's own
  integrity, persistence or publication contract.

If localized, classify the defect as A API/argument contract, B type/container
normalization, C fixture/record shape, D switch/partition interface,
E serialization/publication, F other bounded software defect, or G multiple
defects. Specify a minimal future repair and regression test without implementing
them. The historical numerical evidence is affected only if the localized
operation changes its meaning; localization itself changes no numerical result.
