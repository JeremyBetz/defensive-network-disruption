## Question and boundary

Can the existing provider-independent option-network package satisfy an
experimental public-release contract without changing its scientific behavior?

This is a software session. It may use synthetic fixtures and already committed
public artifacts only. It must not open empirical populations or provider files,
fit a model, recompute scientific results, inspect protected or withheld detail,
or promote a claim. M0/M1 features, utilities, option shares, tie handling and
Session 8 summaries are frozen. Accessibility remains **PROXY ONLY** and
suppression remains **NOT SUPPORTABLE**.

## Release contract

- Promote the distribution from `0.0.0` to `0.1.0`. The release remains
  experimental and pre-1.0; compatibility may change with documented releases.
- Retain distribution name `defensive-network-disruption` and import name
  `defensive_network_disruption`.
- The supported root API contains exactly the ten symbols recorded in the
  companion release contract. Other modules are internal and unsupported.
- Core requires NumPy. The existing `interop`, `dataframe`, `visualization` and
  `public` extras remain separate and composable. Add no runtime dependency.
- Public parameters and returns receive useful type annotations and concise
  docstrings. Errors identify the invalid argument and a corrective action.
- Optional packages remain lazily imported and missing-package messages name the
  appropriate extra.
- Existing research modules remain in the distribution to avoid moving frozen
  scientific code. Their presence grants no public compatibility promise.

alpha status, the public repository, documentation, issues and changelog.
`LICENSE.md` remains canonical. A controlled source manifest will include the
license, README, changelog, contributing guide, API guide, release checklist,

identity mappings, access ledgers, outputs, credentials, signed URLs, local

No tag, GitHub release, PyPI upload, upstream pull request or service deployment
is authorized. Documentation must describe installation from source until a
later release is explicitly authorized.

outputs stops the session and is reported without silent repair. A packaging,
typing, documentation or user-error defect may be corrected before final
closure, with failed checks retained in the research-log chronology when
material. No empirical data may be opened to diagnose software behavior.
