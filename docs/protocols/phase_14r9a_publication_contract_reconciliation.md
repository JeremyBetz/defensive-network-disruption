the prospectively frozen public schema assigns lifecycle, exposure, and
candidate-work authority to `qc.json`. It traces authority, determines whether

## Authority trace and information comparison

The governed diagnosis records the exact function, lines, branch, commit
history, and historical schema origin of the public
`lifecycle_summary.json` lookup. It determines whether R9 explicitly inherited
that public requirement, whether the protocol superseded it, and whether the
checker derives names from the frozen schema or hardcodes historical behavior.

The review maps each intended lifecycle datum to actual frozen QC fields as one
of: `present_exactly`, `present_equivalently`, `missing`, `conflicting`, or
`unavailable`. Required subjects include run status, validation mode,
authorization/unlock state, attempt state, state and edge access, candidate
work, lifecycle completion, exposure uncertainty, active context, and
publication success/failure. Pre-access failure packages may legitimately carry
an uninitialized snapshot; their explicit pre-access mode and null snapshot are
validated rather than fabricated into zero-valued empirical counters.

## Oracles and bounded reconciliation

Before the governed review, discoverable tests exercise:

- a valid nineteen-artifact success package whose lifecycle authority is QC;
- a missing or conflicting QC lifecycle field;
- the stale twentieth-file requirement;
- an optional legacy lifecycle file consistent with QC;
- a legacy file conflicting with QC;
- manifest/schema mismatch;
- a valid failure package with unavailable scientific artifacts;
- an incomplete success package;
- validator-derived success and failure; and
- absence of empirical, numerical, certificate, rendering, and scientific
  routes.

If the trace mechanically establishes diagnosis A or C and QC is authoritative,
R9a adds an isolated prospective validator that reads lifecycle authority
directly from QC, checks the frozen nineteen-name schema, validates output
hashes and private bindings, accepts a consistent optional legacy file without
requiring it, and rejects any conflicting legacy file. It must support strict
success and failure packages. It persists a validator receipt containing the
schema ID, lifecycle representation source, artifact count, checked package
status, and result. Success is derived from this validator.

If diagnosis B is established, R9a does not add a twentieth artifact to R9; it
records that a future protocol must freeze a revised schema. If diagnosis D or
E applies, no repair is attempted. Any unexpected execution or integrity failure
closes F without repair or rerun.
